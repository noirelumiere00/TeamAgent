# search_surface_check 場面ごとの構成（1 本ずつの動画分析への追記）v1

## 追加の指示: 場面ごとの構成（厳守）
この動画は、検索上位の動画の構成表（場面ごとに、何秒から何秒に何を映し、テロップと発話で何を言い、何のための場面か）に使います。上の JSON の `scenes` を次のとおり詳しく出力してください。ほかの欄の書き方は上の指示のままです。

- `scenes` は動画の最初から最後までを、隙間なく時間順に区切る。区切りは内容の変わり目（カット、話題、手順の段）。6〜12 個を目安にし、12 個を超えない（カットが多い動画は、同じ段のカットを 1 つの場面にまとめる）。
- 各場面に次の 4 つの欄を足す。実際に映っている・聞こえることだけを書き、無いものは `null` にする。
  - `role`: その場面の役割。`hook|problem|steps|result|proof|cta|other` のいずれかを完全一致で書く。
    - `hook` は冒頭で見る人を止める場面（最初の場面は通常これ）。
    - `problem` は悩み・問いを言葉にする場面。
    - `steps` は手順・方法・中身の説明。
    - `result` は完成・結果・実演・食べる/使う場面。
    - `proof` は根拠・比較・ビフォーアフター・数字の裏付け。
    - `cta` は保存・フォロー・コメントなどを呼びかける場面。
    - どれにも当たらなければ `other`。
  - `telop`: その場面に出ているテロップの要旨（原文に近く、40 字以内）。テロップが無ければ `null`。
  - `speech`: その場面の発話（ナレーション・セリフ）の要旨（40 字以内）。発話が無ければ `null`。
  - `intent`: その場面が何のためにあるか（見る人に何をさせる・分からせるための場面か）を 1 文・40 字以内。
- `desc` は画面に何が映っているかを 1 文で書く（上の指示と同じ）。
- 秒（`start_sec` `end_sec`）は数値だけ。最後の場面の `end_sec` は実尺にそろえる。

例（形だけ。値は動画ごとに観測したものを書く）:
```json
{"start_sec": 0.0, "end_sec": 2.5, "desc": "完成したカレーの寄り", "role": "hook", "telop": "スパイス4つでいい", "speech": "これ、4つだけで作れます", "intent": "少ない材料という意外さで止める"}
```

## 記号の禁止（厳守・JSON の値にも効く）

`telop` / `speech` / `intent` / `desc` の値はそのまま HTML レポートの構成表に出る。値の中に次の記号を書かない。

- `**` による太字。強調が要るなら語順と言い切りで示す。
- `—`（em ダッシュ）と `--`。文を切るなら句点で切る。
- `→`。矢印で繋がず「A なので B」と文で書く。
- 見出し記号（`#` `##` `###`）と節見出しの絵文字。
  （テロップの要旨は原文の表記のまま書いてよい。秒数などのデータもそのまま書く。）
