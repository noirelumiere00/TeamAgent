# チャンネル名・期間指定（P12）

`slack_summary(channel_name="#proj-01", period="昨日", focus="受注件数と売上を集計")`
で、本人の連携トークンからチャンネルを特定し、指定期間の本文と返信を読む。
名前または期間を指定した場合は `scope` を省略してもチャンネル単位になる。
名前だけを指定した場合の期間は今週。`channel_id` に名前を渡した旧形式も受け付ける。
`今日`・`昨日`・`一昨日`・`今週`（月曜開始〜実行時刻）・`先週`（先週月曜〜今週月曜）・
`先々週`・`今月`（1日〜実行時刻）・`先月`・`直近N日`／`過去N日間`（今日を含めず N 日遡った
00:00〜実行時刻）・`M月D日〜D日`／`M/D〜M/D`（年は今年、未来なら昨年。単日も可）・
`YYYY-MM-DD`・`YYYY-MM-DD〜YYYY-MM-DD`（終日を含む）を JST で解釈する。全角数字も通る。

## 権限と名前解決

現行 `SLACK_USER_SCOPES` に `channels:read` / `groups:read` が無いため、
`conversations.list` は呼ばない。本人の `search.messages` を
`in:#正規化した名前`、次に部分名の検索 `in:#部分名*` で呼び、返されたチャンネル名を
NFKC・小文字化して照合する。完全一致を優先し、複数候補や取り切れない部分一致は選ばない。
部分一致は Slack 検索が返した候補の範囲に限る。投稿が検索に出ないチャンネルや
中間部分だけの名前は解決できない場合がある。未解決は一様の拒否文とし、ID・リンク・
投稿の貼り付けを要求しない。

空チャンネルも含む確実な名前・部分名解決には `channels:read` / `groups:read` の追加と
再連携の判断が必要。今回 OAuth scopes は変更しない。

期間の `conversations.history` / `conversations.replies` は oldest/latest と cursor で
ページ送りする。半開区間 `[oldest, latest)` に ts を再検査し、親の重複を除く。
期間検索で、期間より前に始まったスレッドへの返信も探し、`thread_ts` または permalink の
親時刻から返信本文を取得する。親時刻が得られない投稿は投稿 ts で返信取得を試み、
失敗は一部のみと明示する。検索の抜粋を本文の代用にはしない。

## 停止フラグと上限

| 環境変数 | 既定 | 用途・固定上限 |
| --- | --- | --- |
| `SLACK_SUMMARY_NAMED_PERIOD_ENABLED` | OFF | 名前・期間指定の追加読み取りを止める |
| `SLACK_SUMMARY_NUMERIC_TABLE_ENABLED` | ON | 数字の表の生成指示と確実な数値抽出を止める |
| `SLACK_SUMMARY_PERIOD_MAX_MESSAGES` | 1000 | 履歴と返信合わせて最大1000件 |
| `SLACK_SUMMARY_PERIOD_MAX_PAGES` | 10 | 各 API 最大10頁 |
| `SLACK_SUMMARY_PERIOD_MAX_THREADS` | 10 | 最大10親スレッド |
| `SLACK_SUMMARY_MAX_MESSAGES` | 120 | 要約器へ最大120件 |
| `SLACK_SUMMARY_PER_MSG_CHARS` | 800 | 要約・数値抽出は1件最大4000字 |

期間取得は共通45秒の予算（進行中の1リクエストは最大15秒）で次の呼び出しを止める。
名前解決は別途最大2検索。SDK 自動リトライは新規 reader で無効にしている。
上限、循環／欠落 cursor、返信・補助検索の失敗は `truncated=true` と一部のみの注記。
履歴 API の失敗は取得失敗とし、空の期間と混同しない。

数字の依頼では LLM に項目・単位・訂正・重複・出典を整理させる。さらに単位付き数値
（円・万円・件・人等）を本文から最大40行の参考表に残す。数値表は人名・文章・命令を
転記せず、異なる指標や訂正前後の数字を自動合算しない。指標の意味付けと集計の判断は
要約器によるため、数字の訂正や同じ指標かどうかの判断を決定的な検算として扱わない。

## 死守ライン

本人トークンのみ、read-only、本文の無害化と資料枠、通知トリガ除去、本文・人名なしの
ログを維持する。チャンネル名を解決しても、発信元以外の内容はチャンネルに出さない。
`slack_search` も発信元に一致する公開投稿だけを出し、別場所の一致件数を返さない。
この出力制限は安全性の条件なので解除フラグを設けない。

未連携は本人連携を案内し、検証済み本人・workspace の metadata と OAuth 設定がある
DM だけに既存の本人束縛付き連携リンクを出す。公開と確認済みの会話で `not_in_channel`
が返った場合のみ本人の未参加と伝える。private・公開不明の ACL エラーは既存の一様文。
確認済みチャンネルの履歴・補助検索がともに空なら「該当期間に投稿がありません」。
