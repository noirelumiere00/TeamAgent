## 2. 対象システムの構造（セキュリティ境界）

```
Slack ⟷ OpenClaw外殻（Fargate・最小IAM・Secrets/KMS/RDS/DynamoDBへ明示Deny）
           │  streamable-http MCP（bearer認証・VPC内部のみ・SGで発信元を外殻に限定）
           ▼
        金庫側タスク群（teamagent-mcp / aiia-mcp[構築中]）
           ├ RDS（RLS）・per-user OAuthトークン（DynamoDB+KMS暗号化）
           └ Bedrock（東京リージョン・IAM認証・APIキー不使用）
```

- 外殻（インターネット側）は営業データ・認証情報に**構造的に到達不能**（IAM明示Deny＋ネットワーク分離。IAMシミュレーション＋VPC内実測で確認済み）。
- per-user の Google/Slack 連携トークンは KMS 暗号化＋本人メールアドレスを暗号化コンテキストに使用（他人の行を複製しても復号不能）。
- メール送信機能はコード上に存在しない（読取・下書きのみ）。なりすまし防止（呼出元の自己申告を採用しない本人解決）は単体テストで実証済み。

## 3. 検出事項と当日対応（すべて修正済み）

| # | 重要度 | 検出事項 | 対応（2026-06-12 実施） |
|---|---|---|---|
| 1 | 高 | 連携用Webページ（OAuthコールバック）のエラー表示に反射型XSS（外部から実証可能な状態） | 出力エスケープを出口関数で一括適用＋CSP/nosniffヘッダ付与＋再発防止テスト追加。稼働中プロセスも修正版で再起動 |
| 2 | 高 | Python MCP SDK の新規公開CVE（CVE-2026-52869/52870・2026-06-05公開） | **実環境は本番・新ビルドとも修正版1.27.2で非該当を実証**（ビルドログ・ロックファイルで確認）。依存宣言の下限も1.27.2に固定し契約化 |
| 3 | 中 | 旧検証用 Lambda の Function URL が無認証公開設定のまま残置（組織ポリシーにより実際のアクセスは403でブロックされていたことを外形実測で確認） | Function URL と公開許可ポリシーを削除（公開面そのものを撤去） |
| 4 | 中 | 新規ビルドしたコンテナイメージにOSパッケージ由来のHIGH脆弱性5件（curl/perl・アプリ依存ではない） | Dockerfileにセキュリティパッチ適用を組み込み再ビルド。**再スキャンの結果、当該5件はOSディストリビューション側に修正版が未提供のCVE**（最新パッケージでも残存）と判明。暴露評価=極小（curlはコンテナ内ヘルスチェック専用・perlはアプリ未使用・コンテナは外部非公開）。修正版リリースを追跡し、提供され次第リビルドで取り込む運用とする |
| 5 | 中 | トークン保管 DynamoDB テーブルのPITR（ポイントインタイム復旧）・削除保護が無効 | トークン2表にPITR有効化、関連4表すべてに削除保護を有効化 |
| 6 | 低 | 実トークンを含む一時編集ファイル2件がローカルに緩い権限(644)で残置（git管理外・流出形跡なし） | 削除（正本は600権限で維持） |
| 7 | 低 | 一部リポジトリの .gitignore に terraform 変数ファイル(*.tfvars)パターン欠落（該当ファイルは現存せず実害なし） | パターン追記 |

## 4. 既知の継続事項（認識済み・対応予定あり）

| 事項 | 現状 | 対応予定 |
|---|---|---|
| Slackトークンのローテーション | 構築作業中に作業端末上で扱ったトークン3本（bot/app/user）の再発行が未実施。漏えいの形跡はないが衛生上ローテーション推奨 | パイロット開始前に実施（再発行→Secrets更新→再デプロイ→旧トークン失効確認まで） |

## 5. 最新事例からの教訓と本基盤への適用状況

1. **サードパーティ拡張の汚染キャンペーン**（OpenClaw向けマーケットプレイス経由のマルウェア配布・2026年に複数報告）
   → 本基盤は**マーケット由来の拡張を一切導入しない**（公式プラグイン2点のみ・ビルド時固定）。今後も自作＋コードレビュー済みのみ許可をポリシー化。
2. **OAuthトークン保管庫の窃取事件**（2025年 Salesloft Drift: 顧客のOAuthトークン窃取→700組織超に波及）
   → 教訓は「窃取されても即失効できる体制」。本基盤はテーブルアクセスを最小IAM＋KMSで限定済み。加えて**全ユーザートークン一斉失効→再連携の手順書**を整備予定。
3. **MCPサーバの無認証公開**（2026年上半期に無認証MCPサーバの大量露出が報告）
   → 本基盤のMCPは**インターネット非公開**（VPC内部のみ・SGで発信元限定・bearer必須・トークン未設定時は起動拒否）。VPC内の別ホストからの直接アクセスが遮断されることも実測済み。
