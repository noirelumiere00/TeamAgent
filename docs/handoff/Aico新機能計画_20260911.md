### 2-1. `pre_meeting_brief`（アポ前 事例ブリーフィング）

#### 利用者から見た挙動

**毎朝（定期便）** — 別 DM は増やさない。既存の朝ダイジェスト DM の `📅 当日の予定` の直下に節が 1 つ増える。

```
📌 *本日の社外MTG 事例ブリーフ（2件）*
• `10:00-11:00`  【社外】初田製作所様_新卒採用 ／ 初田製作所（防災機器）・代理店: 電通
  └ <https://docs.google.com/…#gid=0&range=42:42|📍施策事例集 42行目> 新卒採用ショート10本／指名検索+180%（社内担当: 高杉）

• `14:00-15:00`  ○○様 打合せ ／ ○○（社外か要確認）
  └ 該当事例なし（要確認）
_出典: 📍ショート動画施策事例集（行リンク）_
```

- 社外 MTG 0 件 → `📌 *本日は社外MTGなし*` の 1 行。
- **事例集が未取込のときは節そのものを出さない**（「事例集が未取込のためスキップしました」を毎朝 29 名へ送るのは「できません」の定期配信になるため。運用者向けログにだけ落とす）。
- カレンダー未連携者には**週 1 回（月曜のみ）**「カレンダー未連携のため本日のブリーフは出せません。連携はこちら <URL>」の 1 行 DM（毎日送らない）。
- 本日最初の社外 MTG が配信時刻より前に始まる日は、節の冒頭に「⏰ 本日最初の社外MTGは配信より前（9:00〜）です」を 1 行。

**オンデマンド** — 「今日のアポの事例出して」「明日の社外MTGの事例は？」「初田製作所の事例出して」で、**同じ skill・同じ判定**がその場で返す。朝の DM を消しても取り戻せる。`client` 指定時はカレンダーを介さず直接引く（取りこぼし・誤爆の自力回復口）。

**社外 MTG の判定（決定論・LLM を一切通さない）** 評価順は **強シグナル → 弱シグナル → 除外語** に固定する。

| 段 | 条件 | 結果 |
|---|---|---|
| S1 | タイトルに 【社外】【外出】【訪問】【来社】【商談】【打合せ】【テレカン】（NFKC で表記ゆれ吸収） | external |
| S2 | 説明欄に `クライアント：` / `得意先：` 行 | external |
| S3 | 参加者に社内ドメイン（`DIGEST_INTERNAL_DOMAIN`）以外が 1 件以上 | external |

- `ng` → `⚠対外利用NG・口頭のみ`

#### 事例集データの扱い（ここが v1 の生命線）

`data/ingest_sources.yaml:68-94` は「01〜08 の個別エントリ追加は**意図的に書かない**」と明文で禁じている。理由は同ファイルに実見で残っている:

1. **NG 印（`case_external_use='ng'`）はフォルダ由来では守れない。** Drive はファイルが複数フォルダから辿れるため、NG フォルダと通常フォルダの両方に属する 1 ファイルは後勝ちで印が消え、「⚠なしの NG 事例」が朝の DM に載る。
2. **既存の /app タグを壊す回帰**が起きうる。

したがって **v1 の事例母集団はマスター表（gsheets 1 エントリ・二重カバー無し）だけに限定する。** 対外利用可否もフォルダではなく**マスター表の列**を真実源にする。事例 pptx フォルダの取込は別トラックとし、着手前に必ず (a) Drive `files.get(fields=parents)` で `1fraqGng…`（★クライアント展開NG）と `14APBy53…`（03｜事例）の親を実測し既存 spec 配下でないことを確認、(b) 2 spec に跨る file_id が無いことを SQL で実測、(c) `documents` の upsert を sticky キー（`case_external_use` を降格不可）にする改修、の 3 点を前提条件にする。

### 2-2. `clip_proposal`（2秒で切り抜くん）

#### 利用者から見た挙動

**入口** — Aico の DM か依頼スレッドに MP4 を添付して「切り抜き提案作って」。**必須入力は誰向けか（クライアント名）だけ**（要望文の入力定義は「添付 PPT＋MP4」であり、指名検索ワードは提案の一部＝出力）。ファイル名・スレッド文脈・本編冒頭から候補を推定し、受付の即答でエコーバックする:

> 切り抜き提案の作成を始めました。「初田製作所」の素材として進めます。違っていればこのスレッドで教えてください。目安 15 分前後です。できたらこのスレッドに資料を添付します。

**混雑時は再依頼を求めない。** 待ち行列を作り「2 番目で受け付けました。順番が来たら自動で始めます（目安 ◯分）」と返して自動着手・完了通知。日次上限は「1 人 2 本/日＋全体 20 本」に分け、上限文言は「枠が空くのは明朝です。急ぎは小俣さんへ」まで書く。

**処理中** — 「まだ？」に工程で答える（文字起こし中（4分経過）／切り抜き候補を選定中／資料を組み立て中）。`job_id` を覚えていなくても答える（省略時は本人の直近 1 件）。

**完成** — 依頼スレッドへ PPTX を添付（スレッドに出せないときだけ本人 DM）。添付コメントに 4 点:
- この資料は今時点のイメージです。デザインはこれから詰めます。
- 記載の秒数は本編での切り抜き区間です。編集で「えー」「あー」等を落とすため実際の尺は数秒短くなります。
- 界隈の規模は仮定値、界隈言語は実在確認が取れたものだけ素で、取れないものは「（未検証）」と明記しています。
- **今回はモック内が動画ではなく代表コマの静止画です**（テンプレの指示とは異なります。動画埋め込みは次段）。

**できないことを手作業へ突き返さない**
- 長尺は**段階的劣化で必ず解析まで到達させる**（long_edge 1280→720→480→360→240）。品質が落ちた回は「テロップが読み取れなかったため音声中心で分析しました」と明示。240 でも収まらない極端な長尺だけ失敗にし、文言は「分けて添付してください」ではなく「この長さは現在うまく扱えません。担当（小俣）に連絡してください」。
- YouTube URL は本番実測（2026-08-17）で bot 判定に阻まれるため OFF のまま。「URL からは取得できませんでした。動画ファイルをこのスレッドに添付してください」＋ Drive 共有リンク経路（既存 `drive_video` adapter）を代替案内。**添付が来たら同じ依頼として継続**（やり直しをさせない）。

### 6-1. アポ前ブリーフィング（B-9）

**定期便**
2. `MORNING_DIGEST_USERS=s-komata@…` ＋ `MORNING_DIGEST_PRE_MEETING_BRIEF=1` で run-task を 1 回。
3. 本人 DM に 📌 節が出ること、`📅` の直下にあること、事例行にリンクと社内担当が付くこと。

5. 他のメンバーに 1 通も届いていないこと（`MORNING_DIGEST_USERS` が効いている）。
6. CloudWatch `/teamagent/dev/morning-digest` に社名・MTG名・URL・ドメインが出ていないこと。
7. カレンダーに次を仕込んで再実行し判定を確認:
   - 『【社外（外出）】初田製作所様_新卒採用』→ external で事例が出る
   - 『週次ヨミ会』（参加者全員社内）→ 出ない
   - 『田中様 打合せ』（ゲストリスト非表示）→「（社外か要確認）」で出る
   - 説明欄に `クライアント：○○（代理店：電通）` → 「○○・代理店: 電通」
   - タイトルに `<!channel> 至急` → そのまま出力されず 60 字以内に無害化

**オンデマンド（C-9）**

### 6-2. 2秒で切り抜くん（C-10）

**事前**

2. `CLIP_PROPOSAL_USERS=s-komata@…` で点灯（未設定は全員拒否なので、設定前に誤爆しない）。

**E2E**
3. 小俣さんの DM に初田製作所の本編 MP4（90 秒）を添付し「切り抜き提案作って 初田製作所」。
4. 受付の即答が 5 秒以内に返り、クライアント名がエコーバックされること。
5. 3 分後に「まだ？」→ 工程名＋経過分数が返ること（`job_id` を書かなくても答えること）。
6. 15 分前後で同スレッドに PPTX が添付され、注意文 4 点が付くこと。
7. 生成 PPTX を `uv run --extra media python` で開き機械照合:
   - 10 セル全部が埋まっている（空欄が無い、または空欄の理由が DM に出ている）
   - 訴求軸・切り抜きメモ・界隈詳細の**書式**（縦書き・白ハイライト・5/6/7pt）が保たれている
   - 画像 21 枚が正しい枠に入り、hook 枠が歪んでいない
   - **他社名ゼロ**（生テンプレを食わせたときは配達されないことも別途確認）
   - media part が「台帳の許可分＋21 枚」だけ
   - docProps に人名が無い
8. 2 本目を連続 submit → 待ち行列に入り、1 本目の完了後に自動着手すること（再依頼を求められないこと）。
9. 他人が投稿した動画があるスレッドで依頼 → その動画を拾わないこと。
10. わざと cap を超えさせ、PPTX が配達されず失敗として返ること。
11. 24 時間後に S3 の原本・フレーム・PPTX が消えていること。

**受付文の確定**: 実測所要時間が出たら受付文の「15 分前後」をその値に合わせて確定する。
