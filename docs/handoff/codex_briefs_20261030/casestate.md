あなたは teamagent リポジトリの開発者。作業場所はこの worktree（origin/dev 起点）。日本語で報告する。
背景: 社内 Slack AI の全 DM を判定したところ、35 件で「提案中・受注・実績の取り違え」が起きていた（例: 提案しただけの案件を実績・受注として答える、事例の年月や状態を取り違える）。計画上の名前は「数字の正本（PR2）→ 正本から描く（PR3）」。
やること（調査と計画だけ・コードは変えない）:
1. 案件・事例・資料の「状態」（提案中／受注／実施済み／失注など）と「根拠日」がどこから来ているかを、検索（src/teamagent/skills/search ほか）・取り込み（src/teamagent/ingest）・金庫（AiLaVault 関連）・DB スキーマ・回答の組み立てから追い、状態が無い／推測されている／取り違えが起きうる箇所をファイル:行で列挙する。
2. 「状態と根拠日をコードで持たせ、答えではその値だけを使う」設計案を 2 つ（小さい案・本格案）出し、それぞれ変更範囲・データの出どころ（正本が無い場合の扱いを含む）・テスト方法・工数を書く。推奨を 1 つ。
3. 結果を docs/case_state_plan_20261030.md に書く。
禁止: git commit・push、AWS・DB の実接続、.env・secrets の読み取り。顧客名を報告に書かない。
