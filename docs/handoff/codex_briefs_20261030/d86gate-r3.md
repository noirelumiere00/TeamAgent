## A. 本物 FMT の 8 枠（商品画像 1・X 投稿画像 6・SNS 投稿イメージ 1）
- 8 枠は「画像の貼り先」として欄仕様に持つ（検出・挿入の対象）。旧座標の当て推量はやめ、本物 FMT の枠を根拠に特定する。
- 判定は 2 段に分ける:
  - 画像を渡したのに貼れなかった（壊れた画像・枠不足・挿入失敗）→ issue にして draft（取得失敗を成功に吸収しない＝P1-5 の本旨）。
  - 画像がそもそも渡されていない枠 → ready を止めない。warning「要対応: 画像未挿入 N 枠（○枚目…）」として見える化だけする。
- `required_image_spec_missing` は「欄仕様が読めない（FMT が想定外）」ときだけ。本物 FMT では出ないこと。
- 実 FMT テスト: (1) 画像なし → 画像系の issue 0・warning あり、(2) 合成画像を 8 枠ぶん渡す → 8 枠挿入・issue 0、(3) 壊れた画像 1 件 → issue あり。BU2 食品と BU1 美容の 2 種以上。

## B. 見積・試算・ヒアリング等の条件系の欄（決定: 表示のみ・ready 可）
- PLAN・SIM・HEARING・ESTIMATE-NOTES など条件系の欄が空のときは「条件未指定・要相談」と表示するだけ。これを理由に draft にしない（issue に入れず、warning で残すのは可）。
- ヒアリング欄が 0 件のときに 6 枠全部が「条件未指定・要相談」になるのは避け、1 枠目だけ表示して残りは今の「意図して使わない枠」と同じく除く。
- 前回の指示 2（PB-ACCOUNTS など条件系以外は「条件未指定・要相談」にしない）はそのまま。
