## 0. 北極星（North Star）

**「2026-12-28、ベクトル社の営業16名は、月曜の朝7時に、AiLa から届く Slack メッセージで一日を始める。」**

その1通には、

- 今日要返信のメール3本（要約と推奨アクション付き）
- 今週リスクが上がった商談（受注角度低下／返信遅延／競合動向）
- 昨日までに更新された社内ナレッジ・勝ち筋動画・類似提案

が、**「読めば動ける」状態で並んでいる**。スレッドで `@AiLa この案件のドラフト書いて` と打てば、3.3秒で関連ナレッジを引き、95枠の提案 PPTX が Drive 配下に届く。商談メモを `@AiLa これ記録しといて` と投げれば、BANT に構造化されて CRM 相当に積まれ、翌週の進捗サマリーに自動で反映される。

営業は **「探す」「思い出す」「テンプレを開く」をやめ、「顧客と話す」「決める」「動く」だけに時間を使う。**

## 1. 営業の体験で語るペルソナストーリー

### 朝（07:00）— 朝メール秘書
> Slack を開く前に、AiLa の DM が届いている。「今日返信すべきメール3件、要約済み。最優先は A 社の発注確認。下に下書きを置きました。」
> 中山さんは下書きを2行直して送信。**今日の最初の20分を、メールの仕分けに溶かさずに済む。**

### 午前（11:00）— 提案ドラフト
> 商談前に Slack で `@AiLa B 社（CPG 新規）向けの初回提案、過去の勝ち筋テイストで` と打つ。3.3秒で関連ナレッジ12件と類似動画3本が RAG で引かれ、30秒後に95枠 PPTX が Drive 配下に保存され、Slack に permalink が返る。
> **「過去案件を漁る30分」が消える。** 自分は表紙メッセージと差別化ポイントだけ磨く。

### 商談後（16:00）— 営業ログ化
> スマホで `@AiLa B 社、予算500万、決裁は部長、競合は Y 社、来月再提案` と DM。AiLa は BANT に構造化し、案件 ID／担当／フェーズ／受注角度の暫定値を付けて記録。
> **メモアプリと案件管理シートを行き来する手間がゼロになる。**

### 帰り際（18:30）— 横断検索／カルテ
> `@AiLa C 社の過去2年の接点、論点と決め台詞だけ`。Slack・Drive・FB スプレッドシート・動画分析結果を横断し、p95 15秒以内で **「決め台詞だけ」抽出した時系列** が返る。
> **明日の朝イチ MTG に、5分で準備が完了する。**

### 金曜（17:00）— 週次進捗サマリー
> マネージャーには、AiLa から「16名×案件の受注角度マップ」が DM で届く。🔴の案件には「最終接触から14日、返信遅延」「競合動向の言及あり」などの根拠も添付。
> **「週報を読んで動く」マネジメントが成立する。**

## 2. AiLa の Principles（loop も従う 6 原則）

1. **3.3秒の応答が、信頼の基準。** Slack mention への応答 p95 ≤ 15 秒。重い分析は「受け付けました」を即返す。**待たされたら誰も使わない。**
2. **「正しい1件」が、100件のリストより尊い。** 検索は引用元と一次ソースを常に添えて返す。営業が引用元を1クリックで開けることが、AI への信頼を作る。
3. **書く前に、書かれている。** 提案・営業ログ・週次サマリーは、AiLa が下書きを置いた状態から始まる。営業の仕事は「ゼロから書く」ではなく「直して送る」に変わる。
4. **データ隔離は、絶対不可侵。** 他の営業の案件情報は、RLS で物理的に見えない。**「うっかり混線」がゼロであることが、内部 AI に対する心理的安全の条件。**
5. **失敗しても、1分で戻る。** 落ちることはある。落ちたとわかること、誰かが気づいて1分で戻すこと、明日の朝7時の DM がちゃんと届くこと。**運用が静かなことが、最高の UX。**
6. **AiLa は一つ。** メールも、Slack も、Drive も、動画も、TikTok トレンドも、**一つの `@AiLa` で取り回せる。**「メール用 Bot」「動画用 Bot」と複数を覚えさせない。

## 3. 「本番運用開始」とは何か（2026-12-28 のゴール定義）

「コードが動いている」ではない。次の4つが同時に満たされた状態を指す。

| 軸 | ゴール |
|---|---|
| **利用** | 営業16名のうち **13名以上** が週次で AiLa に3回以上能動的にメンションしている（受動利用ではなく、定着） |
| **価値** | 営業の自己申告で「AiLa が今週、合計で〇時間／〇案件分の仕事を肩代わりした」が **月次レポート** として出ている |
| **信頼** | RLS 越権インシデント 0 件・データ漏洩 0 件を3ヶ月連続で達成。情シス監査の月次合格 |
| **運用** | SLO 全緑（p95 ≤ 15s／可用性 ≥ 99.0%／エラー率 < 1%）を1ヶ月連続維持。障害訓練で1分復旧を実証 |

## 4. Success Criteria（loop が日次で照合する 10 指標）

1. **朝メール秘書配信成功率**: 30日移動窓で ≥ 98%（07:30 到達まで含む）
2. **検索レイテンシ**: 中量 Skill（search/proposal_draft/proposal_review）の p95 ≤ 15 秒を1ヶ月連続維持
3. **提案ドラフト満足度**: 月次3問アンケート「直して送れる品質だった」が ≥ 80%（4ヶ月連続）
4. **営業ログ自動化**: operation_log BANT 抽出成功率 ≥ 80%、月間記録件数の80%以上が案件 ID 紐付き済み
5. **ナレッジ鮮度**: ingest 週次成功（last_success ≤ 8日）、月20件以上の新規ナレッジが pgvector に取り込まれる
6. **可用性／エラー率**: MCP 月次可用性 ≥ 99.0%、エラー率 ≤ 1%（24h 移動窓）を3ヶ月連続達成
7. **セキュリティ**: RLS 越権 0・データ漏洩 0 を3ヶ月連続、トークン rotation を期日通り実走（半期1回以上）
8. **障害復旧**: 障害訓練で MCP/OpenClaw タスク異常 → ロールバック ≤ 1分（runbook 通り）。年2回実施
9. **能動利用**: 営業16名のうち13名以上が、過去7日間に @AiLa へ3回以上の能動メンション（30日窓・直近4週連続）
10. **週次進捗サマリー**: マネージャー DM 配信成功率 ≥ 98%、「🔴 案件の根拠が読めば動ける」評価 ≥ 70%

## 7. 設計上の不可侵（北極星を守るガードレール）

どんなにスケジュールが押しても譲らない。

1. **RLS は常に on。** 営業同士の案件は、コードの不具合でも見えない。
2. **本番デプロイは CodeBuild → ECS のみ。** terraform plain apply 禁止・targeted のみ。
3. **トークンは Secrets Manager。** ローテーション運用が文書化され、12月までに少なくとも1回ローテを実走している。
4. **明示ユーザー承認なき本番 EC2 / Fargate 操作はしない。** Agent 側の自律実行は dev 限定。
5. **観測なき機能追加はしない。** 新スキルは usage_events か CloudWatch Logs の構造化ログに必ず計測点を持つ。
