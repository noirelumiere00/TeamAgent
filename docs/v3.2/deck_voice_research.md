## 共通契約

- `voice_evidence.VoiceEvidence`: 取得原文、ID、媒体、URL、タイムゾーン付き取得日時、
  本文SHA-256、取得経路、任意のactor run ID。原文の空白や改行を保持する。
- `quote(start, end)`: 保存原文の連続部分だけを返す。本文ハッシュ不一致・不正なURL・
  不正な取得日時は拒否する。モデル生成の引用本文を受け取る入口は設けない。
- `aggregate_assignments`: 取得済みIDだけを単一主分類へ割り当てる。未知ID・重複ID・
  未定義分類・モデルが生成した件数は採用しない。分類した数と未分類数を分ける。
- `VoiceBatch.status`: `ok_nonempty / ok_empty / partial / failed / skipped / not_requested`。
  成功空結果は今回の標本が0件であり、媒体全体に声がないとは断定しない。

## 取得と費用

`VoiceResearch.collect(targets, ctx, products=...)`が共通入口。Geminiには依存しない。
呼び出し側は1ジョブにつき一度だけ実行し、戻り値の原文証拠を保存してから原稿に渡す。
両資料で同じ証拠・状態・集計を使う。83枚側は今後、Gemini調査結果とこの証拠を別項目で併置する。
Geminiの生成した例文・件数を、一次コメントや口コミへ昇格させない。

- TikTok: 既存Apify actor。異なる動画は4本まで、各100コメント、各取得60秒まで。
  同一URLを二度取得しない。同文でも異なるコメントIDは別件として保持する。
- X: 本人・商品が一致する検証済み投稿だけを30分間再利用。最大64組・各30投稿の
  プロセス内キャッシュ。未検証投稿・別社員・別商品は再利用しない。追加のX検索はしない。
  再起動・別タスクではキャッシュがないため`skipped`となる。永続化・タスク間共有は未実装。
- 取得の概算予約上限は1実行$0.75。現在の4動画×100件なら最大$0.40を予約する。
- 分類はHaikuに固定し、1回$0.05、合計$0.25まで予約する。入力はレコード境界で
  UTF-8 22,000バイトまで、出力3,072トークンまで。自動再試行はしない。
  上限・分類失敗・入力上限による未分類は`partial`として残す。
- 既存Apify月次台帳の予約成功を確認できなければ、新しい有料取得は開始しない。
  この厳格動作は新経路だけ。既存X等の費用台帳の動作を一括変更しない。
- 厳格経路のactor起動POSTは再試行しない。応答不明時は概算費を残す。
  run ID不明の失敗を自動再起動しない。件数単価は既存コードの概算であり、
  契約差・最低料金等を含む請求額の絶対上限を保証するものではない。

## 公開と戻し方

`USE_DECK_VOICE_RESEARCH`は既定OFF。
`DECK_VOICE_ALLOWED_EMAILS`は空=拒否、カンマ区切り=指定者、`*`=本人確認済み全員。
本人確認済みメールがない呼び出しは拒否する。OFF・許可対象外では有料クライアントを初期化しない。
Terraform変数は`enable_deck_voice_research=false`、`deck_voice_allowed_emails=""`。
資料への接続時はfake検証→許可メール1名の試用→レビュー後に許可対象を広げる便で出す。
全員へ出す便でのみ`*`を使う。今回の段1では本番フラグを有効化しない。

既存Xの公開範囲を変更しない。`USE_TIKTOK_COMMENT_TOOLS=false`も維持し、単独ツールは再点灯しない。
共通部品の停止は新フラグOFFで行う。資料本体や公開済みXを停止する必要はない。
現段では資料への実呼び出しがなく、フラグをONにしても資料ページは変わらない。

## 既存ツールの修正

- `tiktok_comment_mining`: 成功空結果と取得失敗を別状態にする。
  各コメントIDの分類から件数を算出し、入力上限の外に残ったコメントは未分類として開示する。
  モデルが出した語彙は実際の原文に含まれるものだけ採用する。
  途中の予算拒否でも、既に取得できた結果と費用を消さない。
- `x_voice_search / x_needs_mining`: 全クエリが失敗したら`failed`とし「0件」と書かない。
  一部失敗・成功部分が空なら`partial`とし、成功した検索の範囲だけを説明する。
