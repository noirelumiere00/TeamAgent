# 動画ライブラリ MCP の商品分類・事例検索

## 解決する問題

従来の「化粧品」は、キャプションだけでなく広い業種タグ「化粧品・美容」にも部分一致し、
再生数順でサクセスなどのヘアケア施策が上位になっていた。

業種と商品分類を分離する。広告主・ブランド・商品名・案件も別項目として返す。
特定ブランドの除外リストや自動分類 Agent は使わない。

## 商品分類

| 値 | 表示 |
| --- | --- |
| cosmetics | 化粧品グループ：makeup / skincare / fragrance / nail |
| makeup | メイク |
| skincare | スキンケア |
| fragrance | 香水・フレグランス |
| nail | ネイル |
| haircare | ヘアケア |
| bodycare | ボディケア |
| other | その他 |

化粧品・コスメ・cosmetics は cosmetics グループの厳密な商品分類フィルターになる。
複数の分類指定は積集合で処理し、矛盾する指定は一致なしになる。
「化粧品・美容」は従来どおり業種として残る。医薬品等の法的分類を推定する機能ではない。

分類は動画詳細の管理者向けフォームで根拠を入力して確定する。未確認の動画を商品分類の
一致結果に混ぜない。既存の vl_video_analysis に product_classification / v1 として保存し、
既存の業種・案件、取込処理、DB権限、OAuthスコープを変更しない。

既存データの自動移行は行わない。配備直後は分類済み商品が少なく、狭い検索では0件になる
可能性がある。サクセスを一律にヘアケアとすることもせず、商品情報を確認して登録する。

## MCP ツール

- get_search_options(field, q): 商品分類、閲覧可能な業種・目的・広告主・ブランドの候補。
  最大200件。has_more が true なら q で候補を絞る。
- search_cases(params): 広告主・案件・自社/他社ごとに集約した事例検索。
  matched_video_count / matched_total_plays は一致分、case_video_count / case_total_plays
  は閲覧可能な案件全体。案件名未設定の動画は unassigned_video_count で別に返す。
- search_videos(params): 従来の条件に product_category / brand / product_name を追加。
  既定は関連度順。明示した plays / new / saves / eng は引き続き利用できる。
- get_video(platform, video_id): 確認済み商品分類、ブランド・商品名、保存率・ENG率も返す。
- ping: 接続確認を維持する。

関連度は商品分類による厳密な絞り込みの後、検索語と広告主・案件の完全一致、本文一致、
その他の一致の順で比較し、同点では再生数を使う。成果の因果や将来の効果を表す指標ではない。

search_videos の match_reasons と applied_filters で一致理由と解釈を確認できる。
分類を指定したときの classification_pending_count は、商品分類を外した他の条件に
一致する未確認動画数であり、指定商品に該当すると判定した件数ではない。

保存率・ENG率は同じ最新スナップショットの総再生数を分母とする小数。0.01 が1%。
欠損・ゼロ分母を0に置き換えない。事例の再生数合計は一つでも欠損があれば null。
取得日・取得元も返す。異なる動画のスナップショットは日付がそろうとは限らない。

## 権限と反映

MCPは library:read の読み取り専用。管理者の判定、非公開制御、認証・更新トークンは従来と同じ。
候補・未分類数・事例全体の集約にも閲覧権限を適用する。商品分類の保存は既存のWeb管理者だけ。
MCPに広告費、レビュー担当者、根拠の原文、ストレージキーを追加しない。

この変更はコードと回帰テストの実装。既存接続の権限拡大や本番データの分類更新は含めない。
配備後はプラグインのツール一覧を更新して、新しい2ツールが表示されることを確認する。
