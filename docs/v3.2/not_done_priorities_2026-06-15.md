## △ Tier 3 — 戦略判断が要る（大物リファクタ・next要件 P0-P5）

13項目（実行基盤）＋7項目（LLM）。**やる/やらない/縮小を決める案件。**

- **重要な事実**: 本番経路が OpenClaw + MCP に移ったことで、`slack_bot.py`(2,186行)・`intent.py`(366行) の god-file 群は**ほぼデッドコード化**（本番依存が外れた）。よって「解体」自体の緊急度は下がった。
- **推奨**: 全部やるのではなく分離。
  - **先行する価値あり**: `CapabilityManifest`（スキル単一登録点）＋ `CapabilityId`（StrEnum型一元化）＝**新スキル追加が頻繁になるなら**保守性に効く。manifest契約CIもここに付く。
  - **後回し/不要化検討**: god-file解体・7ドメイン再編・RetrievalPort/GenerationPort・Settings集約 ＝ デッドコードの整形なので、スキルが増えて実害が出るまで待ってよい。
- **決めること**: 「スキル追加の頻度は今後高いか？」→ 高ければ Tier 1 の後に manifest だけ着手。低ければ backlog。
