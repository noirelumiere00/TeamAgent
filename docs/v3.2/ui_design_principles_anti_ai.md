# AIくささを避けるためのUIデザイン原則（ハンバーガーメニューUI編）

> TeamAgent のデザイン指針。HTML レポート（TikTok/VSEO）・提案書 PPTX・Bot の
> リッチ出力など、**AI が生成する UI/ビジュアル成果物すべてに適用する共通ルール**。
> 生成後に必ずこのチェックリストを通すこと。社内向けなので「簡潔・見やすい」を最優先。

## 1. 目的
AI生成UIの典型的な「臭さ」を人間の手で排除し、本当に使いやすいデザインにするためのガイドライン。

## 2. AIくささチェックリスト（生成後に必ず確認）
- [ ] **カード乱用**：すべての要素をカードで囲っていないか？ → リスト形式を検討
- [ ] **角丸・カプセル過多**：ボタン・タブ・枠の8割以上が角丸になっていないか？
- [ ] **影・装飾の足し算**：影・グラデ・バッジが3つ以上使われていないか？
- [ ] **引き算不足**：本当に必要な要素だけ残っているか？（視認性を損なう装飾は削除）
- [ ] **画像配置**：左寄せで詰まっていないか？ → 右寄せリストを試す

**NG例**：AI生成版（カード＋影＋角丸多用で重い）
**OK例**：添削後（リスト＋余白重視で軽やか）

## 3. 人間らしさを入れるための5原則（実践編）
1. **引き算を最優先**
   「これなくても成立するか？」を毎要素に問う。色数・影・装飾を半分に減らすイメージで。
2. **余白と階層を徹底**
   行間・余白を1.5〜2倍意識。テキストの太さ・サイズで自然に視線を誘導。
3. **画像は右寄せリスト**
   メニュー系UIでは画像右配置＋テキスト左が最もスキャンしやすい（特にモバイル）。
4. **角丸は最小限に**
   ボタン以外は角丸を避けるか、極小（4px程度）に。アクティブ状態はアンダーライン推奨。
5. **機能＞装飾**
   「かわいい」ではなく「見やすい・使いやすい」を最優先。バッジは本当に必要なものだけ。

## 4. AIプロンプトへの組み込み例（次回生成時にコピペ）

UI/ビジュアルを生成するとき、プロンプト末尾に以下を貼って制約する：

```
# デザイン制約（AIくささ排除）
- カードで全要素を囲わない。情報の並列はリスト＋余白で表現する。
- 角丸はボタンのみ（最大4px）。枠・タブ・カードの角丸は使わない。
- 影・グラデ・バッジは画面全体で合計3つまで。装飾より余白で階層を作る。
- 行間・余白は広めに（1.5〜2倍）。文字の太さ・大きさで視線を誘導する。
- 画像を伴うリストは「画像=右、テキスト=左」。左に画像を詰めない。
- 「これは無くても成立するか？」を全要素に適用し、迷ったら削る。
- 配色は3色まで（ベース/文字/アクセント1）。アクセントは1箇所の強調にのみ使う。
- アクティブ状態は塗りつぶしカプセルでなくアンダーラインで示す。
```

## 5. TeamAgent 成果物への具体適用

| 成果物 | 適用ポイント |
|---|---|
| TikTok/VSEO の HTML レポート | カードグリッドを多用しがち → 行リスト＋余白へ。サムネは右寄せ。影は1段のみ |
| 提案書 PPTX（build_proposal.js） | 既に「白黒＋赤アクセント」= 本原則と整合。角丸・影の追加生成を避ける |
| Bot の Slack 出力 | 絵文字バッジの乱用を避ける。情報は箇条書き＋余白で。装飾より構造 |
