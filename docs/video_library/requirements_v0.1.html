構成×動画 相互検索サイト（仮称）

データベースは1つにまとめ、使う人の考え方に合わせて見せ方（出口）を変える。v0.2 では、そのデータベースに何を入れ、構成をどんな形で持つかを決める。

v0.3 の追加（2026-10-29）
  • 求めるアウトプットから逆算した評価項目カタログ（57項目）、目的別の重み、点数の付け方と校正方法を追加 → 評価と点数へ
  • 楢原さん確定の社内の制作基準10項目を、入っていれば加点する要素としてカタログに組み込み。基準を Web 上で変えられる「基準の設定画面」の構想を追加。事業区分4つも楢原さん OK
  • 外部の一般投稿（他人のアカウントのオーガニック投稿）も入れられる形に。評価で決めることは小俣さんが確定

構成データの形（見本）

Format

1本の動画を秒ごとの区間に分け、区間ごとに「役割・テロップ・発話・映像」を持たせる。タグはこの区間から付ける。区間が残っていれば、タグの基準が変わっても付け直せる。

0.0–1.8s冒頭（フック）
「その日焼け止め、塗り直してる？」テロップ大・顔のアップ・問いかけの発話
1.8–6.0s悩みの提示
メイクの上から塗り直せない悩み生活者の原体験・手元の映像
6.0–14.5s本編（実演）
メイクの上からスプレーして崩れないか比べる実演・比較カット
14.5–19.0s商品の提示
商品名と価格を表示価格の明示
19.0–22.0s締め
「保存して試してみて」保存を促す
冒頭：問い型見せ方：実演見せ方：比較切り口：価格明示悩み：メイク崩れ目的：購買

内容は形を説明するための架空の見本で、実在の動画ではありません。

データの流れ

Pipeline
1 · 入力

シートは今のまま

担当者はいまのスプレッドシートに書き続ける。運用は変えない。

2 · 同期

毎日 DB へ

シートの内容を毎日 DB に取り込み、数値は取得日ごとに積む。

3 · 分析

ローカルで構成を読む

新しい動画だけを分析し、結果（区間とタグ）を DB に入れる。

4 · 確認

人がタグを確かめる

確認済みのタグだけを出口に出す。公開可の印もここで付ける。

評価と点数の考え方

Scoring

動画を細かい項目に分け、目的ごとに重みを変えて点数にする。「測った事実」「判定」「点数」の3段に分けて持つのが要点。事実を残しておけば、判定基準や重みを変えても、動画を分析し直さずに点数を付け直せる。

1段目 · 事実測った値をそのまま

例：主題を出したのが 0.8 秒、テロップが 1 秒あたり 7 文字、商品が映った合計が 4.2 秒。良し悪しは書かない。

2段目 · 判定基準に当てて ◎○△

例：主題が 1 秒以内なので ◎。基準はタグ辞書と同じように版を付けて管理し、変えたら付け直す。

3段目 · 点数目的別の重みで 0〜100

同じ動画でも「保存を伸ばしたい」と「購買につなげたい」では点数が変わる。

⑥音量の優先順位：ナレーション＞SE＞BGM音量の優先順位自動
⑦著名人の音声の使用・模倣は厳禁著名人の声AI＋人
⑧企業名・商品名の発音を事前に統一企業名・商品名の読みAI（案件ごとに正しい読みを登録）
⑨商用利用できる音源・素材・SE だけを使う音源・素材の権利人
⑩1本の中の素材の重複は 25% 未満素材の重複率自動

「冒頭2秒の維持60%」のような成果の目安（KPI）は、社内で確定したものは無い。成果の目安は DB の実績から作る。

基準の設定画面（構想）

Settings

判定の基準と重みは、時期によって変わる前提で作る。基準をコードに書かず、DB に「設定」として持ち、社内の画面から変えられるようにする。3段に分けて事実を残しているので、基準を変えても動画を分析し直さずに、その場で付け直せる。

変えられるもの基準・重み・項目の出し入れ

例：「冒頭のカット数」の ◎ を 5〜8 から 4〜7 に変える／「保存」の目的で CTA の重みを上げる／新しい項目を足す・使わない項目を外す。

書き方選ぶだけの形にする

数値の範囲・あり／なし・選択肢、のどれかを選んで値を入れる形にする。自由な式やプログラムは書けないようにして、壊れにくくする。

履歴版を残して比べられる

変えるたびに版を上げ、いつ・誰が・何を変えたかを残す。旧基準と新基準で点数がどう変わるかを、反映前に見比べられるようにする。

変更できるのは管理者（当面は小俣さん）だけ。基準の定義は社内の箱（出口①）の中に置き、公開サイトには出さない。

評価で決めること

10/29 決定

10/29 に小俣さんが確定：評価が逆の4項目は推奨どおり目的別に分ける（評価の軸が複数あってよい）／成果の7分類で始める／指標の定義は下の推奨どおり（算出不可の扱い、オーガニックと広告の分離を含む）。

社内資料どうしで、同じ項目の評価が逆になっているものが4つある。点数を付ける前に、どちらを正とするかを決める必要がある。

項目食い違い推奨（目的で評価を変える）
保存を促す CTA楢原さんの分析では「前面に出ると課題」、検索面チェックでは加点保存の目的では加点、再生・反応の目的では点に入れない。前面に出すぎ（冒頭から保存を促す等）は減点
権威訴求楢原さんの分析では最弱、別のスキルでは「証拠あり」として加点権威だけの動画は △。実演などと組み合わせた場合は点に入れない
煽り・ほめ言葉楢原さんの分析では冒頭の「一択」「神」は負け、別のスキルではフックありとして数える冒頭のほめ言葉は減点、「実は」のような断定の問いかけはフックとして数える。2つを別のタグに分ける
商品を出す早さ楢原さんの分析では企業名始まりが NG、外部調査では購買目的なら5秒以内が有利「企業名・ロゴから入る」と「商品が早く映る」を別の項目にする。前者は減点、後者は購買の目的でだけ加点

目的の一覧

再生・完了・保存・反応・検索・想起・購買の7つで良いか。

推奨：この7つで始める。案件ごとに、どの目的で見るかを選べるようにする。

指標の定義の統一

いまは資料ごとに式や最低ラインが違う。

推奨：保存率＝保存÷再生（%）、ENG率＝（いいね＋保存＋コメント＋シェア）÷再生。値が欠けていれば 0 にせず「算出不可」。再生 5,000 未満は参考値。オーガニックと広告は分ける。完了率は広告データの「再生完了数÷動画視聴数」に限る。
