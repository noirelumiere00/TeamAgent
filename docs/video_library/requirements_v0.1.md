# 構成×動画 相互検索サイト（仮称）要件定義 v0.1（構想段階）

- 作成: 2026-10-29 / 小俣（壁打ち: Claude）
- 状態: **構想**。動画分析・実装には未着手。決定事項と保留事項の記録用
- 発端: 内藤さんとの Slack DM（2026-10-28〜29）。鶴の一声・ならさんも同種のものを希望 → 杉浦さんに相談予定

---

## 1. 目的

- **主目的**: 動画の「構成」と「実際の動画」を相互に検索できるサイトを作る
- 背景: 営業は事例が命（事例が刺されば決まる）。悩み → 動画作り・実績の確認を、人に頼らず一人でできる状態にする
- 位置づけ: 事例検索（Aico の「トレンドメディアの◯◯事例」回答）の延長線上の発展。単なるアーカイブサイトではない

## 2. 利用者・公開範囲

| 項目 | 決定 |
|---|---|
| 利用者 | 営業（提案・事例出し）、制作（構成づくり）、レポート作成 |
| 公開範囲 | **一旦、一般公開**（2026-10-29 小俣さん） |
| 出さない数値 | 広告費・インプレッション・CTR・視聴率など社内/広告管理画面由来の値。公開数値（再生・いいね・保存など）のみ表示 |

## 3. 機能要件

### 3.1 相互検索（中核）

| 入口 | できること |
|---|---|
| 構成 → 動画 | 型を選ぶと、その型の実例動画が数値つきで並ぶ |
| 動画 → 構成 | 動画を開くと、使われている構成・フック・似た型が分かる |
| 悩み・フリーワード → 両方 | 「◯◯したい」から、効く型と実例動画が出る |
| 類似 | 検索結果に似た動画も合わせて出す |

### 3.2 動画の見せ方

- サイト内で動画を全部見せ切らない（再生・いいね・保存は TikTok 側に付けたい：内藤さん）
- 希望順: ① URL 方式で動画を置く → ② サムネイル＋カーソルを乗せると再生
- 方針案: TikTok 公式埋め込みプレイヤー（`https://www.tiktok.com/player/v1/{動画ID}`）をカーソル時だけ読み込み、音なしで再生。クリックで TikTok 本体へ
  - 確認済み: 上記 URL が応答すること（HTTP 200）
  - 未確認: カーソル時の自動再生の挙動、埋め込み再生が TikTok の再生数に入るか
- 動画ファイル自体は自前で保存しない（権利・容量を軽くする）

### 3.3 掲載・更新

- 新しい投稿が出たら自動で掲載される
- 将来: オーガニック投稿・Instagram も追加

## 4. データ要件

### 4.1 元データ（既存）

| データ | 中身 | 備考 |
|---|---|---|
| ショート動画データベース（Google スプレッドシート、`データベース`タブ） | 1行=1動画・40列。動画URL・アカウント・広告主名・案件名・再生/いいね/シェア/コメント/保存・投稿文・広告指標 | 2026-09-15 時点の実測: 案件に紐づく動画 1,151本（45社・54案件）、自社メディアの通常投稿 1,482本。Aico が案件単位で取込済（`teamagent/ingest/campaign_aggregate.py`） |
| 【ベクトルグループ共有用】ショート動画エージェンシー | VCL トレンドメディアのアカウント台帳（約113件、オフショア込みで約147件）・フォロワー推移 | アカウントのマスタとして使う |

### 4.2 付けるタグ（新規・今は無い）

- 構成 / 冒頭のフック / 解決する悩み / 業種 / 目的（認知・理解・購買）
- **構成の分類は実際の動画から作る**。FMT100（VCL の netlify サイト）は仮のもので、実際の動画を分析して出したものではない → **内容の参考に留める**（元データの所在は不明）

### 4.3 サムネイル

- TikTok 公式の埋め込み情報（oEmbed）では、サムネイル・タイトルが返らなかった（1本で確認）→ 別の方法で取得し、自前で保存する必要あり

## 5. 動画分析（構想・保留）

- 方式: ローカル PC で動画を分析し、タグを付ける
- 粒度: 1秒あたり約15フレーム
- 費用感: API（Sonnet 5.5）で全本数をやると、入力・出力とも大きくなり高額になる見込み（小俣さん見立て 約300万円）→ API 一括ではなくローカルで回す前提
- **現時点では実行しない**。構想として保持する

## 6. 基盤（非機能）

- **AWS を推奨**（Vercel も技術的には可能）
  - 理由: データ（RDS pgvector）・Google ログイン・Bedrock・公開経路（ALB/Fargate）を TeamAgent の既存部品から流用できる。Vercel だと社内 RDS への接続と、社外サービスの契約・セキュリティ確認が別途必要
  - 案: 画面は S3＋CloudFront の静的サイト、検索 API は既存 Fargate のイメージに1本追加、データは RDS
- 参考: news-tv.jp は Clipkit（外部 CMS サービス）＋CloudFront で稼働

## 7. 段階（案）

| 段階 | 中身 |
