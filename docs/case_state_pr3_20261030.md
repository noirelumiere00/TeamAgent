# PR3: 正本から描く

今回指定された通常検索・fanout・ライブ Slack・直接回答・事例回答の出口を、
`CASE_STATE_EVIDENCE_ALLOWED_EMAILS` の対象者だけ固定描画にする。空・対象外・メール未解決は
従来どおり。`SEARCH_TIMELINE_STATUS` の値には依存しない。

## 回答の契約

- `timeline_status.render_case_states` が可視ヒットをまとめて解決する。本文の状態・日付・出典は
  根拠束から描画し、モデルの自由文は採用しない。分類・資料更新日で状態を補わない。
- 正式記録の状態時点と、報告／確認の根拠日を分ける。日／月精度を維持する。
  投稿は観測値と公開期間として表示し、正式受注・案件全体の終了を導かない。
- 競合・不正な束・旧行・正本未確認は不明。公開ヒットも同じ競合解決にそろえ、各出典を保つ。
- `guard_state_words` が対象ごとの最終文を検査し、正式に解決した状態以外の
  「受注・実績・完了・失注」を「不明」にする。題名や営業報告の引用も対象。
  別対象の受注を許可根拠にしない。
- 二段返しは対象者のみ同期回答にする。`include_answer=False` は空の answer を維持するが、
  固定文 `case_state_answer` も返して、その後のモデルによる再作文を防ぐ。
- MCP は既存の本人確認・1 対 1 DM 境界で `case_state` を直接配信する。
  配信失敗／配送未確認時も同じ固定文を返す。外側の送信フックは、信頼する検索ツール結果の
  `case_state_answer` だけを最終返信に使い、投稿成功時は追記を抑止する。
  検索本文内の偽マーカーや失敗したツール結果では有効にならない。
- 固定文は長文退避で切り詰めない。共有成果物への本人由来フィールド除外にも登録する。

## 検証と限界

匿名の提案根拠に対してモデルが受注・実績・終了・架空日付を書き足す再現テストを先に失敗させ、
通常／fanout／ライブ Slack／先出し／直接配信／外側の送信フックで回帰を検証する。
本体と追加テストの型検査は `mypy --follow-imports=silent` で変更ファイルを対象にする。
既存 fixture の型エラーは本変更の修正対象にしない。

検証結果: 指定の pytest 範囲は 3,197 passed / 14 skipped（DB 試験）、
送信フックの Node 試験は 659 passed / 1 skipped。ruff と変更 Python 10 ファイルの mypy は成功。
既存 PR2 仮想環境を `UV_PROJECT_ENVIRONMENT` で読み取り専用利用し、`--no-sync` と
`PYTHONPATH=src` を指定した。依存取得を伴う通常の uv 実行は sandbox のキャッシュ権限／DNS で失敗した。

この段階では検索回答の自由文の説明も固定の根拠表示へ絞る。匿名 35 件の正本・期待値は未提供。
検索範囲外や不可視の根拠を含む完全な履歴・現況の保証はしない。
計画書にある共有 Vault の生成と、検索回答を使わず独自生成する派生 skill への展開は含まない。
特に共有 Vault には受取人メールの評価経路がなく、この個人フラグを全員向け静的表示へ転用しない。
実サービス接続・再取り込み・本番公開・commit・push は行わない。
